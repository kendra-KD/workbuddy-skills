## #001 · 2026-10-31 · 首次创建（v1.0）

### 触发场景
用户（运维工程师）需要面向运维/技术支持/SRE 场景的结构化问题上报格式化 Skill，作为副业产品开发第二个 Skill。要求把零散的报错描述+环境信息+已试操作整理成标准化上报报告，跟 ssl-cert-monitor（发现问题）形成产品矩阵（上报问题）。变现路径：免费引流→卖代维服务 + 公众号内容联动。

### 方案选择
- **能力边界**：格式化 + 紧急度分级 + 建议下一步（启发式提示，不诊断根因）
- **输入方式**：对话式（自然语言抽取）+ 表单式（逐字段格式化），两种都支持
- **输出格式**：Markdown 报告（主输出，可直接复制）+ JSON 结构化数据（便于批量统计）
- **技术栈**：Python 标准库 re + argparse，零第三方依赖
- **作用域**：项目级（副业产品，可分发）
- **Fork/从零**：从零设计（广场检索最高契合度 50%，无 ≥70% 同类；现有 bug-report/incident-reporter 都是通用模板，无运维场景结构化模板）

### 最终效果
- 6 个文件，共 1020 行
- 实测全通过：正常路径 5 项 + 失败路径 3 项 + 边界路径 2 项 + 独立工具 3 项

### 关键决策
1. **先剥离已试操作再抽取 error**：第一版 error 抽取会把"已试过重启 minio 进程"吸入 error 字段。解决方案：在 extract_from_text 里先用正则剥离"已试过..."部分，再从剩余文本抽取 error。这是字段抽取的核心架构决策。
2. **紧急度分级独立成脚本**：classify_severity.py 可独立使用也可被 format_report.py 调用，复用性好。
3. **变现引导只加在 Markdown 不加在 JSON**：保证 JSON 数据干净可用于批量统计，变现引导只在人类阅读的 Markdown 报告末尾。
4. **脱敏模式独立开关**：--mask 参数控制，IP 保留前两段，password/token 替换为 [REDACTED]。

### 可复用经验（提炼给后续 Skill）
1. **多字段抽取时，先抽取会"污染"其他字段的字段并剥离**：当 A 字段的匹配范围会覆盖 B 字段的内容时，先抽取 A 并从原文剥离，再从剩余文本抽取 B。比试图用复杂 lookahead 约束边界更可靠。
2. **正则 lookahead 里不要嵌套字符类**：`(?=...[:：]...)` 这种写法容易导致括号匹配错误，改用其他方式实现边界约束。
3. **变现引导只加在人类阅读的输出，不加在结构化数据**：保证数据输出干净，变现引导不影响程序化消费。
4. **独立工具脚本设计**：把核心能力（如紧急度分级）做成可独立运行的脚本，既可被主脚本调用，也可单独使用，复用性更好。
