# 问题上报 · 空白模板

> 直接复制此模板，手动填写后即可作为标准化上报报告使用。
> 也可以让 AI 自动填充——把故障描述发给 AI，说"问题上报"即可。

---

## 问题上报

- **客户名**：[填写客户名，如：浙江白马 / 内部服务 / 无]
- **环境/节点**：[填写环境+节点，如：生产 / 172.22.1.22 / enableai]
- **完整报错**：[粘贴完整报错信息，包括 HTTP 状态码、错误消息、日志片段]
- **已试操作**：[列出已经做过的排查/修复尝试，及结果]
- **复现步骤**：
  1. [步骤 1]
  2. [步骤 2]
  3. [步骤 3]
- **紧急度**：🔴 紧急 / 🟡 重要 / 🟢 普通（不确定可让 AI 自动分级）
- **建议下一步**：
  - [排查方向 1]
  - [排查方向 2]

---

## 填写指引

| 字段 | 必填 | 填写要点 |
|------|------|---------|
| 客户名 | 是 | 没有外部客户就填"内部服务"或服务名 |
| 环境/节点 | 是 | 包含：环境(生产/测试/开发) + IP/主机名 + namespace/服务名 |
| 完整报错 | 是 | 原样粘贴，不要概括。HTTP 状态码 + 错误消息 + 关键日志 |
| 已试操作 | 是 | 写清楚"做了什么 + 结果是什么"，不要只写"试过了" |
| 复现步骤 | 视情况 | 能复现的就写步骤，偶发性的注明"偶发，未稳定复现" |
| 紧急度 | 是 | 影响生产核心服务=🔴，影响部分功能=🟡，仅咨询=🟢 |
| 建议下一步 | 否 | 让 AI 自动生成，或自己写初步排查方向 |

---

## 紧急度自评标准

| 级别 | 适用场景 | 响应预期 |
|------|---------|---------|
| 🔴 紧急 | 生产环境 + 核心服务不可用（502/503/超时/宕机/数据丢失） | 立即响应，5 分钟内有人接手 |
| 🟡 重要 | 生产环境部分功能异常，或非生产环境核心服务不可用 | 30 分钟内响应 |
| 🟢 普通 | 非生产环境部分功能异常，或仅咨询/优化建议/文档问题 | 当天响应即可 |
