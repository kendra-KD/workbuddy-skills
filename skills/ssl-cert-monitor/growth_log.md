## #001 · 2026-10-30 · 首次创建（v1.0）

### 触发场景
用户（运维工程师）需要面向普遍场景的 SSL 证书到期巡检提醒 Skill，作为副业产品开发。要求不绑定特定公司/域名/云厂商，可分发给任意 HTTPS 运维用户。

### 方案选择
- **能力边界**：检查 + 报告 + 续签指引（附各平台续签操作文档，但不自动执行续签）
- **输入方式**：CSV 文件 + 对话临时域名，两种都支持
- **输出格式**：Markdown 表格（按紧急度排序）+ JSON 结构化数据，双输出
- **技术栈**：Python 标准库 ssl + socket，零第三方依赖
- **作用域**：项目级（副业产品，可分发）
- **Fork/从零**：从零设计（广场检索最高契合度 60%，无 ≥70% 同类）

### 最终效果
- 6 个文件，共 1237 行，打包 19.8KB
- 审查打分卡 96/100（≥85 通过，无一维 0 分）
- 端到端实测全通过：正常路径 5 项 + 失败路径 7 项 + 边界路径 4 项 + 安全路径 2 项

### 关键决策
1. **DER 自解析方案**：放弃 `getpeercert()`（CERT_NONE 模式返回空 / CERT_REQUIRED 模式受环境 CA 库限制），改用 `get_unverified_chain()` 拿 DER + `_ssl._test_decode_cert()` 解析。**完全不依赖环境 CA 证书库，任何环境都能跑**——这是本 Skill 可分发性的关键。
2. **issuer/subject 嵌套元组解析**：证书的 issuer 结构是 `((('key','val'),),...)` 三层嵌套，需遍历外层→取内层 `[0]`→再取 key/val。
3. **CSV 读取容错**：`csv.Sniffer().has_header()` 对含 `#` 注释行的样本会抛 `Could not determine delimiter`，需先过滤注释行再嗅探，嗅探失败降级为按表头关键字判断。
4. **报告格式修正**：失败行不能用独立一行显示原因（Markdown 表格会错位），合并到状态列。

### 可复用经验（提炼给后续 Skill）
1. **Python ssl 模块证书提取的正确姿势**：永远用 `get_unverified_chain()` + DER 自解析，不要依赖 `getpeercert()`，不要依赖环境 CA 库。这个方案在任何操作系统、任何 CA 库状态下都能工作。
2. **打包前必须清理 __pycache__**：`python -m py_compile` 会产生 `__pycache__/*.pyc`，打 zip 前必须清理，否则用户解压后会看到垃圾文件。
3. **实测清单先行**：写脚本前先列实测清单（正常/失败/边界/安全四类路径），写脚本时按清单把容错逻辑一起设计进去。比"写完再想测什么"高效得多。
4. **Markdown 表格不能有跨行内容**：任何"额外说明"都不能用独立行塞进表格，必须合并到已有列或放到表格外部。
5. **广场检索要拆词**：搜 SSL 证书 Skill 时，"证书到期检查巡检"整句搜不到结果，拆成"SSL certificate monitor"+"证书到期检查"才有结果。
